# Gitee 项目管理

> 这份只讲**怎么用**。深层细节都拆到 `references/` 了 —— 先看本页，需要时再读对应那一篇，
> 别一上来把五篇全读（费 token 且没必要）。

## 0 先确认入口，别凭记忆拼工具名

| 会话情况 | 模型看到的 MCP 入口 |
|---|---|
| 用了 Gitee 预设（Gitee 项目管理） | 原生工具 `mcp__gitee_ent__<tool>`（55 个） |
| 其它预设 | 一个两级入口工具 `gitee_ent`（`{"op":"list"}` → `{"op":"schema"}` → `{"op":"call"}`） |

拿不准就先 `{"op":"list"}`。工具名、参数名以 `schema` 返回为准 —— 55 个工具里有
`review_enterprise_pull`（审查）/ `test_enterprise_pull`（测试）/ `create_enterprise_repo_pull`（建 PR）
这些看着像但拼错就没法调的坑。

## 1 建 PR：两条路，能力等价

| | 路 1 · 人在面板填 | 路 2 · AI 调 MCP |
|---|---|---|
| 入口 | 合并请求页 / 仓库详情页「＋ 新建 PR」 | `create_enterprise_repo_pull` |
| 谁填参数 | 人填表（可「套用模板」/「✨ AI 起草」） | 模型填参数 |
| 链路 | `POST /pr/create` → 宿主校验 → 同一个 MCP 工具 | 直连 MCP |
| 适合 | 一次性填完、要立刻看 PR 详情 | 批量 / 从 diff 与工作项自动写标题正文 |

两条路都能设审查人数、测试人数、草稿。**源/目标分支是下拉**：面板走宿主
`GET /repo/branches`（企业版 `/projects/{id}/branches`，MCP 没有列分支工具）；只有默认分支的仓库
会直接说「先推开发分支」，不让白填。

PR 模板两份：`templates/pr.md`（干净骨架——「套用模板」原样插入）、
`templates/pr-guide.md`（带每节填写说明——面板「写什么？」展示，也是「✨ AI 起草」的写作要求）。
AI 起草 = 宿主抓 `compare`（源 vs 目标分支的真实提交与文件差异）→ 在所选主会话下起子智能体
→ 返回 `{title, body}` 填进表单，仍可手改。
「投递到」那行有胶囊勾选框**子智能体**（默认勾选）：勾选 = 纯后台；取消勾选 = 结论同时落进主会话
（DSH `delivery: 'parent'`，会话里看得见），**两种都自动回填表单**。

## 2 三条纪律

1. **list → schema → call**：不要靠猜参数；报错先读原文，别急着重试。
2. **不猜 id / 分支名 / `state_id`**：一律先查（成员、项目、仓库各一次），查不到就问用户。
3. **写操作先看权限位**；合并、删除、改权限这类不可逆动作只按用户明确指令做。

## 3.5 数据时效：每次都要说清楚数据有多旧

看板数据是**缓存**的（默认新鲜期 60 秒，可在「设置 → Gitee 企业项目 → 缓存与后台刷新」里改（保存即生效，不用重启）），
所以 `gitee_board` 与 `gitee_board_snapshot` 的输出里都带一行：

`> 数据时效：内存缓存，抓取于 42 秒前，新鲜期内（60 s）。fetchedAt=… stale=false ttlSeconds=60`

- `stale: true` = **已过期**：回答里必须写明「这份数据不是最新」，并建议刷新（`refresh=true` 或点面板「⟳ 刷新」）。
- 只读缓存不联网：用 `gitee_board_snapshot`（拿不到就说明没快照，改用 `gitee_board`）。
- 不要自己推算时间，也不要假设「刚拉的就是最新」——用输出里的 `ageSeconds`。

## 4 硬规则

- **不猜**：企业 id、成员 id、分支名、`state_id` 一律先查再填。查不到就问用户。
- **不用企业 token 做 curl / api/v5 集成**，也不把 token 写进任何会提交的地方。
- **不改代码去绕过**「写通道已关闭」「乐观锁版本过期」「模板缺失」—— 这三条都是刻意的。
- **合并、删除、改权限**只按用户明确指令做，且先确认权限位。
- 具体业务判断（这个 PR 该不该合）永远由人拍板。
